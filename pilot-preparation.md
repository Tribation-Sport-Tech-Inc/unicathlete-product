# Pilot Preparation

## Objective

Identify which recurring value athletes and individual scouts may eventually pay for, and define how the free closed pilot will measure demand for it.

## Scout Side

The following features could potentially be included in a future paid tier for individual scouts.

### Advanced Search

**Why would scouts pay?**

Basic filters can produce a large athlete pool that requires extensive manual profile review. Advanced filters and the option to search using a recruiting-project description could produce a smaller, more relevant shortlist and save the scout time.

**What to track:**

- Whether the scout uses basic filters, advanced filters, or a project description.
- Which search fields are used.
- Number of results returned.
- Profiles opened before the first save or evaluation.
- Time to the first save or evaluation.
- Percentage of searches that lead to a save or evaluation.
- Repeat use of advanced search.
- Searches that return no results.

### Athlete Comparison

**Why would scouts pay?**

When a scout has two to four similarly suitable athletes but needs to create a smaller shortlist, side-by-side comparison removes the need to repeatedly open and close individual profiles. It could save time, make detailed comparison more convenient, and reduce the chance of overlooking important information.

**What to track:**

- Comparisons created and number of athletes included.
- Time spent using the comparison.
- Comparison sections viewed.
- Individual profiles opened during or after comparison.
- Comparisons that lead to a save, evaluation, or pipeline action.
- Saved comparisons reopened later.
- Repeat use across different sessions or projects.

### Saved Searches and Alerts

**Why would scouts pay?**

Scouts may repeatedly use the same recruiting criteria. Search history, intentionally saved searches, project creation from search criteria, and new-match alerts reduce the need to rebuild searches or manually check for new athletes.

The four capabilities to test are:

1. Search history.
2. Saved search criteria.
3. Create a recruiting project from search criteria.
4. Notification when a new or updated athlete matches the criteria.

**What to track:**

- Searches reopened from history.
- Searches intentionally saved.
- Saved searches reopened or modified.
- Projects created from search criteria.
- Alerts enabled and disabled.
- New matches generated and alerts opened.
- Athlete profiles opened from an alert.
- Saves, evaluations, or pipeline actions resulting from an alert.
- Scouts returning to the product because of an alert.

### Capacity and Advanced Workflow

Saving athletes to a project, evaluating them, writing notes, and advancing them into the pipeline are essential parts of the core scout workflow. Rather than charging for these individual actions, the paid tier could provide greater capacity and more advanced workflow functionality.

**What to track:**

- Active projects per scout.
- Projects created, archived, reopened, and duplicated.
- Saved athletes per project.
- Active pipeline athletes per project.
- Scouts reaching proposed project, saved-athlete, or pipeline limits.
- Evaluations started, completed, revisited, and updated.
- Notes created and revisited.
- Athletes moved through pipeline stages.
- Repeated projects using similar criteria.
- Use of match-score, evaluation-score, and priority sorting.
- Requests for project templates, custom evaluation criteria, exports, or extended history.

These measurements can help determine whether a paid tier should include multiple active projects, higher project capacity, reusable templates, custom evaluations, advanced ranking, exports, or extended history.
